# Avya Jewels — frontend

The storefront customers use (Ivory Editorial design, teal with the dark navigation bar). Plain HTML, CSS and JavaScript — no build tools needed. It talks to the Laravel backend in [`../backend`](../backend) and uses product photos from [`../assets`](../assets), so keep the three folders side by side.

## How it connects

1. `js/api-loader.js` reads the API address from `js/site-env.js`, loads `/api/site` (settings, categories, reviews) and `/api/products`, then starts the shop (`js/app.js`).
2. Products, prices, photos, categories, delivery options, the WhatsApp number and reviews come from the backend — edits in the admin panel show on the next page load.
3. Checkout sends the order to `/api/orders`; the backend saves it (e.g. `AVY-1002`) and returns the WhatsApp link the customer sends.
4. If the API can't be reached, the site uses its built-in catalogue (`js/catalog-real.js`, `js/catalog-purple.js`) and checkout opens WhatsApp with the order directly.

## Settings — `.env` only

```
cp .env.example .env              # then set AVYA_API_URL to your backend, e.g. https://api.yourdomain.com/api
node build-env.js                 # writes js/site-env.js, which the browser reads
```

Run `node build-env.js` again whenever `.env` changes. On Vercel it runs automatically (see `../vercel.json`) using the values in Vercel → Settings → Environment Variables. The backend must list this site's address in its `FRONTEND_URLS`.

## Files

| File | What it is |
|---|---|
| `index.html` | the page |
| `css/styles.css` | all styles |
| `js/app.js` | the shop: pages, bag, checkout, search |
| `js/data.js`, `js/categories.js`, `js/catalog-real.js`, `js/catalog-purple.js` | built-in content and catalogue (used when the backend is off) |
| `js/api-loader.js` | loads data from the backend before the shop starts |
| `js/site-env.js` | generated by `build-env.js` from `.env` — committed, so Git deploys carry it |
